# Altered Draft Simulator — Project Memory

Multiplayer booster-draft + sealed simulator for the Altered TCG. React (Vite) + Tailwind + Supabase Realtime. No backend. Deployed on Vercel at https://altered-draft.vercel.app

## Environment / workflow
- Developed on **both Windows and macOS** — check which you're on first.
  - **macOS:** bash; Node available (`/opt/homebrew/bin/node`). On a fresh checkout `node_modules` may be absent — run `npm install` once, then verify with `npm run build` (vite) before pushing.
  - **Windows:** use the **PowerShell** tool for git. Node may NOT be on PATH there — if `npm`/build is unavailable, verify by reasoning and rely on the Vercel deploy.
- `git push 2>&1` may print to stderr / show a red wrapper even on success — that's normal, check the last line for `main -> main`.
- Commit + push after each change so Vercel auto-deploys (push to `main`). Repo: github.com/nicokwakk/altered-draft. Commit author already configured.
- GitHub blocks pushes exposing the private email — user's noreply email is already set in repo config.

## Card data
- Source: `https://raw.githubusercontent.com/PolluxTroy0/Altered-TCG-Card-Database/main/SETS/{SET}/{SET}_{LANG}.json`
- Root is a **plain array** (NOT `hydra:member`).
- Key per-card fields (see `src/lib/cardData.js` `normalizeCard`):
  - `mainFaction.reference` → faction (AX/BR/LY/MU/OR/YZ)
  - `rarity.reference`: verbose strings → normalized codes: COMMON→`C`, RARE→`R1`/`R2` (R2 if ref ends `_R2`), UNIQUE→`U`, EXALTED→`EX` (also `_E` ref suffix). EX treated as rare in packs.
  - `cardType.reference`: HERO / CHARACTER / SPELL / LANDMARK_PERMANENT / EXPEDITION_PERMANENT / PERMANENT / TOKEN. TOKENs excluded from draft.
  - **Card images: the community CDN, built from the reference — do NOT use the DB/API `imagePath` field.** Altered disabled public access to BOTH its S3 buckets (`altered-prod-eu` AND `altered-dev` now return `403 AllAccessDisabled`) and retired `api.altered.gg` (DNS gone), so every `imagePath` in the community DB and the cards API points at a dead host. `cardImageUrl(reference, lang)` (in `cardData.js`) builds the URL from the ref against `https://cdn.alteredcore.org/cards/<lang>/<SET>/<REF>.webp` (web-optimized, CORS `*`, deterministic — no per-card hash; `<lang>` = lowercase `en/fr/es/de/it`, `<SET>` = `ref.split('_')[1]`). Both `normalizeCard` and `normalizeAlteredCore` set `imagePath` via this helper. **Uniques** (`…_U_<serial>`) aren't on the CDN, but a unique shares the illustration of its base RARE printing, so `cardImageUrl` falls back to `…_R1` for them. (The old `prodImage()` dev→prod host-swap is removed.)
  - `elements.MAIN_COST` etc. are wrapped in `#...#` markers — `stripMarkers()` removes them. Heroes have mainCost 0 (ignore for cost curves).
- `COREKS` (Kickstarter) has its own dataset; `apiSetCode()` is identity (do NOT remap to CORE).
- **Uniques** (`…_U_<serial>`, e.g. `ALT_CORE_B_AX_04_U_1437`) aren't in the community set files. `fetchUnique`/`fetchUniques` resolve them. The 24 cube uniques are **bundled locally** — data in `src/lib/uniquesData.js` (`UNIQUES_EN`), images in `public/uniques/<ref>.jpg` (served at `/uniques/<ref>.jpg`) — so EN works offline/instantly. `fetchUnique` serves the bundled EN copy first (no network), then for any other unique / non-EN locale fetches live from **`cards.alteredcore.org/api/cards?reference=<ref>`** (the community API that REPLACES the retiring `api.altered.gg` — so we no longer depend on the dying API), falling back to the bundled EN snapshot on failure. That source's JSON shape differs (per-locale `name`/`imagePath` objects, nested `faction.code`/`rarity.reference`/`cardType.reference`, flat power ints) so it has its own adapter `normalizeAlteredCore` (NOT `normalizeCard`); its `imagePath` field is ignored (points at the now-dead S3 buckets) — the image URL is built from the reference via `cardImageUrl` (community CDN, `_R1` fallback for the unique's art). CORS: `cards.alteredcore.org` reflects the request Origin, so the browser fetch works from the deployed site. Bundling more local uniques is now just an offline/perf hedge, not a deadline. (`api.altered.gg` is no longer called anywhere.)
- **Printing variants:** reference is `ALT_<SET>_<PRINT>_<FACTION>_<NUM>_<RARITY>`. `<PRINT>`: `B` = real booster card, `A` = alternate-art reprint (12–36/set), `P` = promo (0–18). A/P are the same gameplay card as their B twin. `fetchSet` filters to **B only** (`isStandardPrinting`) so each card has one canonical printing — otherwise dedup-by-name could keep the alt-art `A` (e.g. Mechanical Training showed `ALT_CORE_A_AX_22_C` instead of `_B_`). Every A has a B twin; only 2 promo-exclusive P cards (ALIZE OR_48, BISE BR_64, high numbers) lack a B and are intentionally dropped.

## Booster composition (`src/lib/packGenerator.js`)
**Pool size is mode-driven** (Lobby `BOOSTERS_PER_PLAYER`): each mode targets a number of boosters PER PLAYER — booster/rochester/rotisserie 4, **winston 6** (= 12 total for 2p ≈ 72 cards each), sealed 7. `bpp = boostersPerPlayer(mode)` replaces the old hardcoded 4 across every draft generation path (presets, cubes, custom pool, multi-set target/validation). Presets generate it automatically; the Boosters/Multi-Set source asks the host to reach the target; cubes generate up to it.
13 cards: 1 hero + 9 commons (1 per faction + 3 paired draws AX|BR, LY|MU, OR|YZ) + 3 rares (1-in-8 packs swaps last rare for a unique). `generateAllPacks(cards, players, packsPerPlayer, {includeHeroes, cubeMode})`. Pools deduplicated by `name+faction`. `splitPools()` helper shared by all generators.
**Optional "Add random uniques" mode** (StartSettingsModal toggle → `config.addUniques`, booster-based modes only — NOT cubes, which manage their own uniques): standard set files carry NO uniques, so normal preset/sealed/multi-set drafts have none. When enabled, each booster gets an INDEPENDENT 1/6 chance its LAST slot becomes a real unique (vs the default deterministic 1-in-8), drawn from a pool of real uniques fetched live per set via `fetchRandomUniques(setCode, count, lang)` (`cards.alteredcore.org/api/cards?rarity=UNIQUE&set.reference=<SET>&random=1&itemsPerPage=N` — `set.reference` == our internal set code; the API registers every opened unique so the pool is effectively unlimited; faction filter is ignored/broken but unneeded). Threaded through `generateAllPacks` (flat `options.uniquePool`), `generateChaosPacks`/`generateStructuredPacks` (per-set `options.uniquesBySet`), and `generateOnePack(…, randomUniqueRate)`. **Perf:** the `random=1` query is ~1.5s (server-side random sort over millions of rows — page-offset is fast but returns all-one-base-card, so `random` is required), so Lobby PREFETCHES the pool the moment the toggle is on + the settings modal is open (`getUniquePools` memoizes by set-codes+lang in a ref; a `useEffect` keyed on `showStart/addUniques/active-set state` warms it), and `handleStart` just awaits the same promise → Start stays snappy. The injected unique refs (serialized `_U_<serial>`) land in `state.packs`/`sealedPacks`/`picks` but aren't in set data or the cube ref list, so Draft/Sealed/Results each scan the live state with `uniqueRefsIn(state)` and `fetchUniques()` the results to render them (resolved by-reference like cube uniques; image host-swapped dev→prod via `prodImage`).
**Cube mode** (`generateCubePacks`, used only by the cube-DRAFT path): each card appears at most once, and EVERY pack is the SAME size (unequal packs deadlock the pass rotation — see Draft logic). It does NOT force 9C+3R structure (that depletes pools unevenly and breaks mid-sized cubes). Instead: 1 hero/pack when heroes ≥ totalPacks (else heroes fold into the body or are excluded), then an equal `bodyPerPack = min(13 - heroSlot, floor(body/totalPacks))` cards from the shuffled commons+rares+uniques; leftovers unused. So pack size scales with cube size (e.g. 147-card cube, 4 players → 16 packs of 9). Sealed cube uses normal boosters (`cubeMode` off), NOT this.
**Multi-copy cubes** (`cube.heroDraft` flag, e.g. LuigiNico's): a cube may run intentional duplicate copies. The Lobby cube-draft branch builds the pool as a MULTISET (`cube.refs.map(r => byRef.get(r))`, NOT a dedup filter). If the cube defines a `booster` recipe it deals with `generateCubeRecipePacks(cards, players×4, recipe)`; otherwise with `generateCubeDraftPacks(cardObjects, totalPacks)` — shuffle, equal packs of `min(13, floor(n/totalPacks))`, no dedup, no hero slot.
**Fixed booster recipe** (`cube.booster = { commons, rares, uniques }`, e.g. LuigiNico's `{3,8,1}` = 12-card boosters): rare-heavy cubes can't use the classic 9C+3R split. `generateCubeRecipePacks` deals each pool (C / U / rest=rares — **Exalted counts as a rare**, `rarity !== 'C' && !== 'U'`) WITHOUT replacement so intentional duplicate rares survive, but RECYCLES a pool (reshuffle + redraw) once it's exhausted — so the scarce 27-common pool repeats across boosters to always hit 3/pack (commons can repeat across boosters but never within one). Every pack is the same size (rotation requirement). Verified: at 2/3/4 players all packs are 12 = exactly 3C+8R+1U, no intra-pack dups, uniques never repeat (24 ≥ 16 packs), rares only "repeat" when the cube genuinely lists 2 copies. **Both DRAFT and SEALED use this same recipe** for a `booster` cube (sealed deals 7 recipe boosters per player; Lobby sealed-cube branch fetches uniques + uses the multiset pool, and `Sealed.jsx` fetches the cube uniques so the unique slot renders). **Sealed hero slot:** built-in hero-draft cubes have no sealed equivalent of the in-app hero draft, so each of the 7 sealed boosters gets a hero in **slot 0** via `dealHeroSlots(packs, heroRefs)` (heroRefs = `cube.heroes` filtered to loaded cards), making 13-card boosters (1 hero + the 12-card body) for BOTH the recipe path (LuigiNico) and the `generateAllPacks` path (All Sets). Heroes are shuffled per player and dealt distinct until the pool is exhausted, then repeat. The sealed-cube branch now includes `cube.heroes` in `setsForCube` so their sets load (and land in `config.sets` for `Sealed.jsx`). `dealHeroSlots` is a no-op when `heroRefs` is empty (non-hero-draft cubes unaffected); pasted custom cubes still fold heroes into the pool instead. `CubePreviewModal` also folds Exalted into the Rare count for `booster` cubes. Restricted to 2–`cube.maxPlayers` players (default 4).
**In-app hero draft** (`cube.heroDraft` + `cube.heroes` = the hero pool; both LuigiNico and All Sets use 12): heroes are NOT in the card packs — they're snake-drafted from ONE shared pool of all the cube's heroes, **one hero per player after each card round**, until each player has `heroTarget` = `min(3, floor(pool/players))` heroes → **3 at 2-4 players, 2 at 5-6**. (Earlier booster/segment designs were scrapped as over-complex; this is the simple version.) Turn-based: after a card round, `applyPick` pauses into phase `heroDraft` (round + remainingPacks left INTACT); players take ONE hero each in **snake order** (`heroOrderFor(players, passIndex)` = seat order, reversed on odd passes) from `state.heroPool`; when the pass completes `applyHeroPick` resumes the card draft at the next round (popping `remainingPacks`), or sets `done` after the final round. So heroes are drafted after rounds 1..heroTarget; rounds beyond that are pure cards. `buildInitialState(config, players, cardPacks, heroPool)` (heroPool = `shuffle(cube.heroes)`) computes `heroTarget` and seeds `heroPool`/`heroTarget`/`heroPassesDone:0`/`heroPicks`. State fields: `heroPool`/`heroTarget`/`heroPassesDone`/`heroOrder`/`heroTurnPos`/`heroPicks`. Only the seat at `heroOrder[heroTurnPos]` may pick (enforced in `doPick`'s `canPick` and `applyHeroPick`); same optimistic-concurrency `version` write. Drafted heroes are merged into each seat's pool on the Results page (`heroPicks` ++ `picks`, heroes first) so they appear in All Picks / deck / export — the player still puts only 1 hero in the actual deck (validity = ≤1 hero). `Draft.jsx` is phase-aware: same `CardGrid`/`doPick`/timer drive the shared pool, with a "Hero Draft — You have X/N heroes" header, a "Waiting for <name> to pick a hero…" notice off-turn, and a "Heroes you've taken" strip; the card draft resumes (Round N/4) after each pass. Lobby + Draft navigate to `/draft` for BOTH `heroDraft` and `drafting` phases. (Replaced the old manual `HeroDraftInfo.jsx` panel, deleted.) **All Sets cube** also uses this now: its 12 heroes were moved out of `refs` into `heroes` (cards 336→324), `heroDraft:true`, `maxPlayers:6`; its cards deal via `generateAllPacks` cubeMode (no `booster` recipe), LuigiNico's via `generateCubeRecipePacks`.
**Personal cubes via paste** (`config.customCube`, NO accounts/storage): the Cubes tab has a "＋ Paste your own cube" panel (name + decklist textarea). `parseDecklist(text)` (`src/lib/cubeParser.js`) tokenises `<qty> <REF>` lines (the Export format; also tolerant of space-separated runs and a `Nx` qty) → refs-with-duplicates (refs only — no name resolution, since the Altered API is retiring). On Parse, `handleParseCube` (Lobby) first **canonicalizes each ref via `canonicalCardRef`** — alt-art (`_A_`), promo (`_P_`), and promo/OP set codes like `DUSTEROP` (= DUSTER OP) map to the standard `B` printing of their base set (e.g. `ALT_DUSTEROP_A_AX_98_C` → `ALT_DUSTER_B_AX_98_C`), since `fetchSet` only stocks `B` cards and would otherwise drop them. Uniques are left as-is (fetchUnique handles them); unknown sets with no known base stay unresolved. Then it fetches the refs' sets + bundled uniques, **auto-detects heroes** (`cardType === 'HERO'`) and splits them out, keeps duplicate copies, and collects **unresolved refs** into a callout (skipped, never silently dropped). Stored INLINE as `config.customCube = { name, cards:[refs], heroes:[refs] }` (no `cubeId`) so all seats sync via Realtime. **Draft:** `generateCubeDraftPacks(cardPool, players×4)` on the non-hero multiset (equal packs); heroes use the shared-pool snake hero draft when `uniqueHeroes ≥ players`, otherwise they fold into the card packs (so none are lost). **Sealed:** heroes STAY in the pool, each player gets 7 multiset packs via `generateCubeDraftPacks(pool, 7)`. Player cap auto-derived (blocks when too few cards: draft needs ≥ players×4 non-hero cards, sealed ≥ 7). Preview reuses `CubePreviewModal` with a synthesized `{ name, author:'You', cardCount, refs }`. Custom + built-in cube selection are mutually exclusive. `Draft.jsx`/`Results.jsx`/`Sealed.jsx` resolve uniques from `config.customCube` (cards+heroes) as well as `cubeId`.

**Out-of-faction cards = the R2 printing (NOT a relabel).** Altered prints each card number in up to three rarities that encode faction: `_C` = common (home faction), `_R1` = rare (same faction as C, may have different cost/stats/effects), `_R2` = rare in a DIFFERENT faction (the "out-of-faction"/OOF/"o" print — its own faction, art, AND stats). So an OOF card is a genuinely different card object: use its real `_R2` ref, whose `mainFaction` already IS the OOF faction. NOTE: the ref string keeps the home-faction letters (e.g. `ALT_ALIZE_B_YZ_45_R2` reads "YZ" but `mainFaction` is AX) — so derive faction from the card OBJECT (`mainFaction`), never by parsing the ref. A card wanted in two columns appears as two distinct refs: `_R1` in its home column, `_R2` in the OOF column. This makes any per-card `cube.factions` override unnecessary (an earlier faction-relabel/token hack was removed once refs were corrected to R2). `CubePreviewModal` parses refs offline but prefers the loaded card's `mainFaction` for faction. **Uniques (`_U_<serial>`) are left as-is** — a unique legitimately exists in either faction the card is printed in; do NOT swap a unique to R2 or override its faction.
**Multi-Set draft** (config tab `multiset`, draft only — merged the old Advanced + Chaos tabs): ONE per-set selector + a checkbox "All players receive the same packs" (default ON, `config.equalPacks`). The selector's required total depends on the toggle (`MultiSetSelector` `target`): **ON → counts are PER PLAYER, sum = 4** (the 4 rounds); **OFF → counts are the WHOLE BAG, sum = players × 4**. Both modes deal **single-set boosters** (normal composition, never a merged multi-set pool):
- **ON (structured/equal):** `generateStructuredPacks(cardsBySet, perPlayerMix, playerCount, {includeHeroes})` — expands the per-player counts into one set per round (`{CORE:2,BISE:2}` → `[CORE,CORE,BISE,BISE]`) and gives EVERY seat that round's set, so all players draft an identical, set-pure experience. Returns the flat pack array laid out BY ROUND to match `buildInitialState` (`allPacks[round*playerCount + i]`).
- **OFF (random/chaos):** the counts ARE the whole bag (sum = players × 4), passed straight to `generateChaosPacks(cardsBySet, mix, {includeHeroes})` — single-set boosters all shuffled together, dealt one random pack per seat per round. (Same behavior/control as the old Chaos tab.)
- Stored as `config.multiSetMix` (per-player when ON, whole-bag when OFF) + `config.equalPacks`. UI: `MultiSetSelector.jsx` (number inputs + the toggle; `target` = 4 when ON, `players × 4` when OFF). Custom-pool textarea (override) lives here too. The old `ChaosSelector.jsx` + `config.chaosMix` were removed. `generateChaosPacks` is still used (Multi-Set OFF + all non-cube sealed).
**Sealed booster generation:** presets/advanced sealed ALSO build single-set boosters via `generateChaosPacks` (a booster never mixes sets). Preset = 7 boosters of the one set; advanced = per-set counts from `SetSelector` (count literally = # single-set boosters of that set; total = pool size, NOT forced to 7). Stored as `config.packMix`. Only **cube** sealed uses a merged pool (curated pool, boosters mix the cube's sets — intentional). Pre-2026-06 bug: presets/advanced sealed merged all sets → packs contained mixed-set cards; fixed.

## Draft logic (`src/lib/draftLogic.js`)
Pure transitions. `applyPick(state, idx, ref)`. Pass left rounds 1&3, right 2&4. `pickDeadline` (timer) format is `"<ISO>|<seconds>"` — MUST split on `|` before `new Date()`. `buildInitialState` seeds `version: 0` (REQUIRED — the optimistic-lock filter matches on it).
**Optimistic concurrency (Draft.jsx `doPick`):** players pick from their own packs simultaneously, so a blind write clobbers concurrent picks. `doPick` does a conditional update `.eq('id', code).eq('state->>version', expectedVersion).select('id')`; if it returns 0 rows (conflict), it re-fetches the latest state and retries (≤12 attempts, jittered). `inFlightRef` is a hard lock against overlapping invocations (timer + click), separate from the `picking` UI flag (which realtime clears on every update). All packs in a round MUST be equal size or rotation deadlocks (official sets always yield 13-card packs: 1 hero + 9 commons + 3 rares).

## Supabase
Single `draft_rooms` table: `id` (room code), `state` jsonb, `created_at`. RLS allows anon read/insert/update. pg_cron job `cleanup-old-rooms` deletes rooms >24h hourly. Realtime subscription on row UPDATE drives all clients. Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Player uses the new publishable key format.

## Re:Union authentication (Keycloak OIDC) — optional/additive
Lets users log in with their official **Re:Union** account (to load cubes from their decks + save pool/deck — both built, see below). **Login is optional**: logged out, `user` is null and everything works anonymously. Keycloak, realm `players`, **confidential** client `altered-draft`, issuer `https://auth.altered.re/realms/players`. **Authorization Code + PKCE**; the code→token exchange runs in a **Vercel serverless function** `api/token.js` that holds the secret (`process.env.KEYCLOAK_CLIENT_SECRET`, set in Vercel env — NEVER in git/bundle). Flow: `ReunionButton` → `login()` redirects to Keycloak with PKCE+state → `/auth/callback` (`AuthCallback.jsx`) posts the code to `/api/token` → `fetchProfile()` reads the pseudo from userinfo. **Token handling (BFF hardened):** the **refresh token never touches JS** — `/api/token` stores it in an **httpOnly, Secure, SameSite=Strict cookie** (`reunion_rt`, `Path=/api/token`); the browser keeps only the short-lived **access token in memory** (`session` var in `reunion.js`). Refresh = POST `/api/token {grant:'refresh_token'}` with NO token in the body (the function reads the cookie, rotates it, returns a fresh access token); `getAccessToken()` does this when near expiry or on a fresh page load. A readable, non-sensitive `reunion_auth=1` hint cookie (`Path=/`) just tells `isLoggedIn()` a session exists (so anonymous loads skip the refresh probe). Logout = POST `{grant:'logout'}` clears both cookies. Files: `src/lib/reunion.js` (OIDC client), `src/auth/AuthProvider.jsx` (`useAuth()` context: `user`/`login`/`logout`/`getAccessToken`), `src/pages/AuthCallback.jsx`, `src/components/ReunionButton.jsx` (rendered on Home). `vercel.json` rewrite excludes `/api/` (`"/((?!api/).*)"`) so the SPA fallback doesn't swallow the function. **Prereq for live login:** the dev must register redirect URIs `https://altered-draft.vercel.app/auth/callback` + `http://localhost:5173/auth/callback` on the client. Scopes: `openid profile`.

**Deck read/write (step 2)** — the two payoff features, both via the **Re:Union decks API** at `https://decks.alteredcore.org` (contract reverse-engineered from `Altered-Community/alteredcore-website`'s `equinox-deck-import` plugin). That API has **no browser CORS**, so calls go through same-origin **Vercel proxy functions** that forward the user's Bearer token: `api/decks/index.js` (GET list / POST create) + `api/decks/[id].js` (GET detail). Frontend client `src/lib/decks.js` (`listDecks`/`getDeck`/`createDeck`/`toDeckCards`/`deckCardsToRefs`) attaches `Authorization: Bearer <getAccessToken()>`. **Load a cube from your decks** (Lobby Cubes tab, "⬇ Load from your Re:Union decks"): `listDecks` (fetches the WHOLE list — `itemsPerPage=1000&order[name]=asc`, since the API paginates at 20/page) → the picker has a **name search box + format-filter chips** (filtered client-side; list summaries carry `name`/`format`/`isDraft` but **no card count**, so a deck-size filter isn't possible there — name/format is the supported fallback) → pick → `getDeck` → `deckCardsToRefs` → `resolveCubeRefs` (`src/lib/cubeResolve.js`, the shared refs→`{cards,heroes,unresolved}` resolver also used by paste) → `setCustomCube({…, source:'reunion'})`; the loaded cube has a **Preview cube →** button (reuses `CubePreviewModal`). `customCube.source` (`'paste'`|`'reunion'`) just drives which Cubes-tab panel shows the selected/summary state. **Export / Save** (`ExportMenu.jsx`, one dropdown on Results + Sealed top bars, replaces the old `SaveToReunion` + dual `ExportButton`): copy complete card list / copy decklist (altered.re format), and — when logged in — **Save your pulls** (pool, `isDraft:true`) + **Save your deck** (`isDraft:false`). Both saved as **`format:'sandbox'`** (valid enum `standard|nuc|singleton|singleton_nuc|sandbox`; sandbox skips collection/legality validation so drafted cards aren't rejected), named `"<code> · <Draft|Sealed> <pool|deck> · DDMM"`; shows `deckbuilder.alteredcore.org/decks/{id}` links. Create payload: hero is just a `deckCards` entry; refs are already uppercase `ALT_…`. Logged-out users see a Connect affordance instead. The decks-API contract (format enum, query filters, schemas) is from its live OpenAPI at `https://decks.alteredcore.org/api/docs.json`.

## Conventions
- Plain React hooks, no useCallback for handlers that read changing state (caused a stale-closure bug where cube sealed always used CORE — avoid).
- **Theming: light + dark via semantic tokens** (mirrors alteredcore.org). Components use semantic Tailwind colors — `base`/`surface`/`surface2`/`surface3` (backgrounds), `ink`/`ink2`/`muted`/`faint` (text), `line` (borders), `accent`/`accent2`/`on-accent` (gold) — defined in `tailwind.config.js` as `rgb(var(--c-*) / <alpha-value>)`. The two palettes live in `src/index.css` (`:root` = dark default, `:root[data-theme="light"]` = parchment); the active theme is set on `<html data-theme>` by `src/lib/theme.js` (+ anti-FOUC inline script in `index.html`). **Do NOT use raw `gray-*`/`amber-*`** for chrome — use the tokens so both themes work. Status (green/red) + faction colors (`ax/br/ly/mu/or/yz`, `FACTION_COLORS`) stay literal/theme-independent. `ThemeToggle` (☀/☾) sits in `TopNav` (the rounded "menu pill" on Home/Lobby) and the Draft/Sealed/Results top bars. Cinzel = `font-display` (wordmark/titles).
- Mobile: `md:` breakpoint splits desktop/mobile layouts. Responsive grids `grid-cols-3 sm:4 md:5 lg:6`.
