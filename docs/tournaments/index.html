1. What the feature is

Re:Union runs online sealed tournaments of the Altered TCG. The tournament (pairings, rounds, results) lives on BoardGameArena (BGA). The sealed part, opening a pool of boosters and building a deck from it, lives on altered-draft (altered-draft.altered.re). When a BGA game starts, BGA asks for the player's deck through altered-bga-api (bga-api.altered.re), which answers the sealed deck list straight from altered-draft, while the deck content still comes from altered-core-decks-api (decks.alteredcore.org), which validates the deck against the player's pool by calling altered-draft back.

Two ways a sealed configuration is chosen

  • Declared tournaments (§14): an organizer declares a BGA tournament on altered-draft with its own configuration (7 boosters of one set, heroes, uniques, ban list). Its players get a pool built from that configuration.
  • The current competitive format (a row in current_format, seeded by sealed-pools-schema.sql) for the two generic flows: the casual "normal" pool and the "prepare my next tournament" pool used for BGA tournaments nobody declared.

The seeded current format

FieldValueMeaning
typesealedOnly sealed is supported; draft is explicitly deferred.
set_codeEOLESet 6, Roots of Corruption.
unique_count1One unique inside the boosters (replaces a rare slot).
guaranteed_uniques1One extra unique handed out outside the boosters.
even_factionsfalseUniques drawn freely across factions.
heroes_in_poolfalseHeroes are not opened in boosters; every hero of the set is appended to the pool.

So a pool of the current format is 7 boosters × 12 cards (9 commons + 3 rares, one of the 21 rare slots swapped for a unique) + 1 guaranteed unique + all EOLE heroes.

The two cheating vectors

Re-rolling the pool

Killed by a one-shot commitment: a player gets exactly one pool per declared tournament (unique (sub, tournament_ref)), and can hold only one pending generic tournament pool at a time, unlocked (a new one becomes mintable) only once a real BGA tournament binds to it.

Playing cards outside the pool

Killed by server-side validation: the pool is generated once from a seed and stored on the row (cards, boosters); decks-api checks deck ⊆ pool against it before handing deck content to BGA. Invalid → HTTP 422 → BGA shows "This deck is not legal".

Not builtDraft tournaments, a signed attestation (the SEALED_ATTESTATION_SECRET env var is provisioned on AlteredOps but unused by any code), an end signal for BGA tournaments nobody declared (declared ones have an end date and a manual close), automated cleanup of old pools.

2.3 Player journeys

Declared tournament journey (§14)

  1. An organizer declares the tournament on /tournament/new with the BGA link and its sealed configuration. It shows in the public "Upcoming" list of /tournament.
  2. The player opens the tournament page (/tournament/t/:id) and follows its checklist: register on BGA (remembered in the browser, BGA registration can't be verified) → Open my pool (one stored pool per player, built from the tournament's config, created pre-bound to the tournament's BGA id) → build the deck (synced to decks-api).
  3. When a game starts, the BGA deck-list call lands on that pool directly (§14.2). A player who never opened altered-draft gets the pool created by that first call, with a random deck, like in the generic journey below.

Generic tournament journey (BGA tournaments nobody declared)

  1. The player opens /tournament/prep any time before the tournament. A pending pool is minted on first visit and stays locked. They build a deck; it is saved under their Re:Union account as a sealed-format deck.
  2. They register to the tournament on BGA. BGA's schedule is the start of the rounds, so the deck has to be built before.
  3. The first game starts. BGA asks altered-bga-api for the deck list with format: SEALED and the tournament id. altered-bga-api calls altered-draft, which binds the pending pool to that id (one-time write), records the game, and returns the linked deck summary. If the player never built a deck, altered-draft mints a random legal deck named Random … so the game can start. On the BGA side the sealed format skips the preconstructed-deck wizard and goes straight to the fetch flow; the single returned deck is auto-selected. A name starting with Random shows a warning ("You didn't build your deck before the matches started…"); a name starting with Invalid stops there with a link to fix the deck on altered-draft; an empty list shows "No Sealed deck found" with a link to altered-draft.
  4. The pool now appears under "My pools", and a new pending pool is available for the next tournament. The player may edit the bound deck between games; every BGA deck-content fetch re-validates it.
  5. BGA fetches the deck content through altered-bga-api → decks-api. decks-api validates deck ⊆ pool by asking altered-draft for the pool linked to that deck id. Invalid → 422 → "This deck is not legal".

Normal (casual) journey

Same screen, for non-tournament BGA sealed games. A BGA deck-list call without a tournament id resolves to the player's normal pool. The player can reset the pool every 30 minutes; resetting deletes the linked deck on decks-api (best-effort) so decks-api never validates against a stale pool.

2.4 Interactions with other Re:Union surfaces

  • altered.re / deckbuilder.alteredcore.org: the synced deck is a regular deck in the account (format: sealed, isDraft reflecting validity). Editing it there goes through decks-api's generic save, which validates against the pool too (by deck id). decks-api refuses to change a deck's format to or from sealed.
  • BGA: only through altered-bga-api (§9.2). The BGA table option "Deck format = Sealed" (option 155, value 7, OPTION_DF_SEALED in AlteredBGA) selects the format; its description tells players decks must be built on altered-draft.altered.re. The BGA client links to https://altered-draft.altered.re/edit/deck/<deckId> ("change your deck between games", "fix it"), which is the /edit/deck/:deckId deep link above.
  • End-of-game stats (altered-bga-api POST /games/register): separate feature that stores games per BGA tournament id. Not wired to sealed pools, but keyed on the same ids as sealed_pools.tournament_id, so a join is possible later.

2.5 Known functional limits

  • "My pools" only grows: pools are never archived. Declared tournaments show their status (upcoming / ongoing / ended / cancelled) next to the pool; generic ones have none.
  • Validity differs slightly between altered-draft (≤ 1 hero) and decks-api (exactly 1 hero). A 30-card deck without a hero shows "Valid" in the app but is rejected by decks-api and BGA (§12).
  • The pool contents are visible to the player before the tournament, by design: only the validated deck counts.

4. Pool generation: determinism and composition

One entry point: buildPool(sub, { config, nonce }) in src/lib/poolBuilder.js, fed by src/lib/prng.js, src/lib/uniqueFactionRanges.js, src/lib/packGenerator.js (generateTournamentSealedPool) and src/lib/banlist.js. config is the sealed configuration object of spec §5.1 (src/lib/tournamentConfig.js): a declared tournament's config, or the current format converted by configFromLegacyFormat.

Generate, then storeEvery pool is generated once, in memory, then inserted with its cards and boosters in one INSERT … ON CONFLICT DO NOTHING RETURNING * (poolStore.insertPool; a normal-pool reset does the same in its UPDATE). A card-data failure throws before anything is written; a lost insert race discards the generated pool and re-selects the winner's. Readers call loadPool(sub, row) (api/_lib/tournamentPool.js): the stored contents, or, for a row created before storage existed, regeneratePool (the same buildPool on the row's snapshot columns, bit for bit the old output).

4.1 Seed

seedStr = sub | set_code | unique_count | even_factions | heroes_in_pool | guaranteed_uniques | nonce
  • sub is the verified Keycloak subject; nonce is a crypto.randomUUID() minted when the row is inserted (or on a normal-pool reset).
  • tournament_id is deliberately NOT part of the seed: a pool must have identical contents before and after binding (fixed 2026-08-12).
  • uniques.faction is not part of the seed either (nor of the snapshot columns): it only narrows the unique candidates, so a config without it draws exactly as before. A pool with a faction only exists as a stored pool (declared tournaments, 2026-10), never regenerated.
  • Two PRNG streams derived with FNV-1a (hashSeed) + mulberry32: mulberry32(hashSeed(seedStr)) for the booster draws and the unique-slot placement; mulberry32(hashSeed(seedStr + '#uniques')) for the unique draws.

4.2 Steps (buildPool(sub, { config, nonce }))

  • Booster composition (generateOnePack with rng): optional hero slot (only if includeHeroes), 9 commons (1 per faction + 3 paired draws AX|BR, LY|MU, OR|YZ), 3 rares. No unique slot of its own. Pools deduped by name+faction in splitPools.
  • Unique injection: after the 7 packs are built, all (pack, rareSlot) positions (7×3) are shuffled with the booster rng and the first uniqueRefs.length receive the uniques.
  • Unique drawing (pickDeterministicUniques): uses the bundled tables src/lib/data/factionRanges/<SET>.json = { family_id: { faction: [[start, end], …] } }, from real production data. Each rare family (e.g. AX_106) has a serial range split into non-contiguous windows between its home faction and exactly one out-of-faction pairing (per card, not a fixed axis). A draw picks a (family, faction) weighted by serial count, then a serial uniformly within that faction's windows, and composes ALT_<SET>_B_<family>_U_<serial>. faction: 'AX' (config.uniques.faction) makes AX the target of every draw: only (family, AX) candidates, i.e. uniques whose real faction is AX, out-of-faction prints of other factions' cards included (every set has 14 to 41 such families per faction). Otherwise evenFactions: true round-robins target factions (the config drops it below 2 uniques and whenever a faction is set). Dedupes within one call (so booster and outside uniques never overlap); an optional isAllowed(ref) predicate redraws refused refs (the ban list). Sets covered: CORE, COREKS, ALIZE, BISE, CYCLONE, DUSTER, EOLE. FUGUE has no table: a declared tournament can't ask for uniques on it (config validation), and buildPool throws when fewer uniques than requested can be drawn instead of returning a smaller pool.
  • Guaranteed uniques and appended heroes belong to counts but to no booster. The frontend shows the guaranteed unique(s) as an "8th booster" ("unique refs in cards that are in no booster").
  • loadPoolCounts is the flat-counts-only variant used by validation callers.
  • Ban list: excludeBanlist (declared tournaments only; the current format leaves it off) removes banned cards from the set before generation and banned families from the unique draws.
  • Card rendering resolves uniques live per ref (fetchUniques → cards.alteredcore.org; image = the base _R1 art on the CDN).

4.3 Why pools are stored

The generation is deterministic (same seed → same pool), and pools used to be regenerated on every read. But the draws pick cards by index in the upstream set file's order: a card inserted or reordered upstream would silently change every regenerated pool mid-tournament and invalidate decks. Storing the generated pool removes that dependency for every new pool; scripts/freeze-sealed-pools.mjs (make db-freeze-pools, run once after the migration, idempotent) stores the older rows. Every consumer (pool pages, BGA deck list, decks-api validation) reads the same stored contents through loadPool.

5. Pool lifecycle and tournament binding

A sealed_pools row is one of four things, distinguished by kind, tournament_id and tournament_ref:

Every later BGA call for the same tournament returns the same row; nothing changes on it except the informative tournament_name of a bound legacy pool (a declared tournament keeps its altered-draft name).

Rules implemented in src/lib/poolStore.js:

  • getOrCreateNormalPool(sub) / getOrCreatePreparationPool(sub): SELECT, else build a pool from the latest current_format with a fresh nonce and INSERT it with its contents. Insert races absorbed by ON CONFLICT … DO NOTHING + re-select.
  • Declaring a tournament (tournamentStore.createTournament), or moving it to another BGA id, adopts every legacy pool already bound to that BGA id in the same statement and the handler imposes their format on the tournament (mixed formats → 409 bga_tournament_mixed_formats); see §14.2.
  • getOrCreateTournamentPool(sub, tournament, { createdBy }): the attached pool, else a legacy pool already bound to the tournament's BGA id (adopted: tournament_ref, the altered-draft name and adopted_at set, contents unchanged, its deck is already in play), else a new stored pool from the tournament's config, created pre-bound (tournament_id = the BGA id, bound_at = now). Races on either unique index (ON CONFLICT on one, a caught 23505 on the other) re-select the winner. The INSERT only goes through while the tournament row is not detached and still holds the config the pool was built from (INSERT … SELECT … FROM (SELECT 1 FROM tournaments … FOR SHARE)), so a config edit or a detach committed during generation never leaves a pool with a stale config: the pool is rebuilt from the re-read tournament (3 attempts), else tournament_unavailable / pool_unavailable, which the handlers answer with a 409, never a 500.
  • bindTournamentId(sub, tournamentId, tournamentName) (the BGA path): (1) if a row (sub, tournament_id) exists → return it (refresh tournament_name only on a legacy row); (2) else, if a live declared tournament has that BGA id → getOrCreateTournamentPool (createdBy: 'bga'); (3) else take (or create) the pending pool and UPDATE … SET tournament_id, tournament_name, bound_at = now() WHERE id = $1 AND tournament_id IS NULL; lost race → re-select. Idempotent: every game of the same tournament re-triggers it. Binding frees the "pending" slot, so the next /api/tournament-prep-pool mints a new pool.
  • resetNormalPool(sub): 30-minute cooldown on reset_at; new nonce; rebuilds and stores the pool from the active format; clears deck_*; returns previousDeckId for the handler to delete on decks-api.
  • recordGamePlayed(poolId, gameId) / countGamesPlayed(poolId): deduped by the composite PK.
  • getPoolById(sub, id), getPoolByDeckId(sub, deckId) and getPoolForTournament(sub, id) are always owner-scoped (never resolve a pool by id alone).
  • listBoundTournamentPools(sub): "My pools", declared tournaments first, then most recent first, with the declared tournament's name / dates / status columns (LEFT JOIN).
Which id gets boundaltered-bga-api forwards BGA's tournamentParentId when the envelope carries one, else the stage's own tournamentId. A multi-stage BGA tournament (Stage 1 groups + Stage 2) therefore binds one pool for the whole event.

6. Deck synchronisation and naming conventions

The deck lives on decks-api; altered-draft keeps only a summary on the pool row (deck_id, deck_name, deck_hero_ref, deck_faction, deck_card_quantity). Two writers keep both sides consistent.

Frontend sync (TournamentPoolView.jsx, throttled 2 s)

  • Runs after every deck change once the deck is non-empty. Skipped when the state is merely seeded from a load or a reset (skipNextSyncRef), so opening the page never renames a Random … deck.
  • Computes validity and builds { name, deckCards, isDraft: !valid, format: 'sealed' }.
  • syncDeckToPool (src/lib/poolDeckSync.js): updateDeck(deckId) then syncPoolDeck(poolId, summary) (POST /api/tournament-pool?id=) if the pool has a deck. A new deck (none yet, or a 404 because it was deleted from the deckbuilder) is created as a draft, linked with syncPoolDeck, and only then, if valid, PATCHed to isDraft: false: the same sequence as ensureDeck below. Creating an already-valid deck ("Random deck": 30 cards at once) as non-draft made decks-api validate it before the link existed: the deck was stored as illegal ("Could not verify your sealed pool") until a later edit (fixed 2026-10-17).
  • One save at a time (createSerialRunner, src/lib/serialRunner.js): an edit while a save runs queues ONE more run, which reads the pool and the deck at run time (syncOnceRef). Two overlapping saves of a brand-new deck used to both see "no deck yet" and each create a deck on decks-api. If the flip off draft fails, the link is kept (the next save flips it) rather than reported as a failure that would create yet another deck (fixed 2026-10-18).

Backend reconciliation (ensureDeck, on every BGA deck-list call)

  • If the pool has a deck with cards: GET it on decks-api. 404 → gone, re-mint. Other failures → trust the cache.
  • Re-derives from the live card list: format forced to sealed, isDraft = !valid, name rebuilt from the pool. Any drift is PATCHed and the summary refreshed.
  • If there is no deck (or empty/gone): buildRandomDeck from the pool (loadPool), POST as isDraft: true first, link it to the pool, then PATCH { isDraft: false }. decks-api validates non-draft decks by calling back /api/tournament-pool-by-deck and caches a failure for 30 s per deck id, so validating before the link exists would poison the cache.

9.2 BGA → altered-bga-api

The AlteredBGA game code (modules/php/States/SetupTrait.php) builds the envelope itself with base64_encode(json_encode(...)) (standard base64 with padding; altered-bga-api accepts base64 and base64url alike) and calls BGA's platform functions get_player_decks / get_player_deck_content. BGA's platform then calls altered-bga-api with the player's Re:Union bearer token and appends tournamentId and gameId as raw query params (the game code never sets them). The only free-text fields the game code controls are eventFormat (deck list) and {id} (deck content), hence the envelope. env is the BGA game name (altered, or the test instance's name), mode is BGA table option 201 (the rating mode, hence sometimes a bare number). tableId is sent as a string.

Deck list

GET /api/bga/decks?eventFormat=<b64>&tournamentId=605019&gameId=555111&page=1&name=&faction.reference[]=…

{ "v": 1, "env": "altered", "mode": 1,
  "payload": { "format": "SEALED", "tableId": "123456", "tournamentName": "Winter Cup - Stage 2",
               "tournamentParentId": 597924, "tournamentGroup": "A" } }

tournamentName / tournamentParentId / tournamentGroup come from BGA's $this->bga->tournament->getInfo() (name, tournament_parent_id, tournament_group) and are null outside a tournament. altered-bga-api's DecklistPayload reads format, tableId, tournamentName, tournamentParentId; tournamentGroup is ignored on this call. The game code keeps eventFormat out of the request it echoes back to its client: the client replays that request on pagination and faction changes, and BGA's validateJSonAlphaNum guard rejects base64's + / =.

AsymmetrytournamentId and gameId are raw query params added by BGA's platform on the request itself, not envelope fields. tournamentParentId only travels in the envelope (AlteredBGA #630). Reading tournamentId from the payload was the 2026-08-12 bug that made every sealed call fall back to the normal pool.

12. Invariants, pitfalls, and how to extend

12.1 Invariants (do not break)

  1. The seed string excludes tournament_id and includes exactly the six snapshot columns + nonce, in that order. Adding a column to the seed changes every legacy (unfrozen) pool.
  2. One pending tournament pool per sub, enforced by the partial unique index; binding is a one-time UPDATE … WHERE tournament_id IS NULL.
  3. Pools are generated once and stored (generate, then insert in one statement); readers go through loadPool. Only rows created before storage are regenerated, until frozen.
  4. Owner scoping: every lookup is (sub, …). Never resolve a pool or a deck by id alone.
  5. /api/tournament-bga-decklist returns the exact hydra shape of decks-api's collection endpoint; altered-bga-api relays it byte for byte.
  6. A SEALED request never falls through to decks-api in altered-bga-api, whatever happens.
  7. Invalid and Random prefixes are literals matched on the BGA side; never localize them. The base name always tracks the tournament name (no dates).
  8. Create every new deck as isDraft: true first, link, then flip (backend ensureDeck and frontend syncDeckToPool): decks-api caches a failed validation for 30 s per deck id.
  9. PATCH to decks-api uses application/merge-patch+json.
  10. heroes_in_pool = false means every hero of the set is in cards; decks-api relies on that instead of an "any hero" carve-out.
  11. JSON imports use with { type: 'json' } (plain Node on Docker enforces it).
  12. New API handlers must be registered in server/index.js as well as existing as api/*.js.
  13. current_format is append-only; never UPDATE it.
  14. A declared tournament's config and BGA link are frozen once a pool exists (checked atomically in the UPDATE); name, description and dates stay editable in every status.
  15. jsonb parameters are JSON.stringify-ed (pg turns JS arrays into Postgres arrays).
  16. Config-only options stay out of the snapshot columns and the seed (uniques.faction today): regeneratePool rebuilds from the columns, so such an option is only valid on pools stored at creation, which every declared-tournament pool is.

12.2 Pitfalls observed in history

  • Reading tournamentId from the envelope instead of the query string (fixed 2026-08-12).
  • Including tournament_id in the seed (fixed 2026-08-12).
  • Reading AlteredDraft:BaseUrl as a required startup binding broke every format in prod (now lazy, per request).
  • Express 5's req.query is a live getter: Object.assign on it is lost; server/index.js uses Object.defineProperty for route params.
  • Validity mismatch: altered-draft ≤ 1 hero vs decks-api exactly 1 hero. A hero-less 30-card deck is "Valid" in the UI, saved as isDraft: false, then rejected by decks-api (and BGA).
  • decks-api caches pool-by-deck for 1 h: a normal-pool reset deletes the deck precisely so the stale cache entry can never be hit again.
  • api/tournament-pool-counts.js binds as a side effect; calling it casually with a tournamentId consumes the player's pending pool.
  • pickDeterministicUniques yields fewer uniques when a set has no faction-range table (FUGUE); buildPool now throws in that case, and a declared tournament can't ask for uniques on such a set. A legacy row on such a set with uniques would fail to load: check before deploying (TESTING.md).
  • Anyone can declare any BGA id (squatting): handled by the moderator-only detach (§14.5).
  • Pasting a BGA stage link instead of the parent tournament's would make every BGA call miss the declaration; the form says to paste the main tournament link, and the organizer panel warns when a started tournament has no pool "created by BGA games".
  • BGA applies its own checks on top of decks-api's validation when it loads the content (actGetDeckInfos): a unique must carry its content and an implemented power, and Moonlight Jellyfish uniques are refused as suspended by Equinox, even though decks-api's sealed validator allows banned cards. Irrelevant for EOLE pools, relevant if the format moves to a set with such cards (CORE).

12.3 Recipes

Run a tournament with its own configuration

Declare it on /tournament/new (§14); no database change.

Change the competitive format of the generic flows

INSERT INTO current_format (…). Existing pools keep their snapshot. If the set has no factionRanges/<SET>.json, add that table first and import it in uniqueFactionRanges.js. Update the backend fallback names (baseDeckName) and the i18n strings that still say "set 6".

Add a field to the pool response

Extend poolResponse in api/_lib/tournamentPool.js; a new column goes in sealed-pools-schema.sql with ADD COLUMN IF NOT EXISTS; mirror it in the tournamentApi.js consumers.

Add a tournament endpoint

Create api/tournament-<name>.js (or a file under api/tournaments/) exporting a Vercel-style handler, start with verifySub / verifyUser, use poolStore.js / tournamentStore.js for data access, register it in server/index.js, add a client function in src/lib/tournamentApi.js, and an integration test.

Expose games played or results

gamesPlayed is already in every pool response. Actual results live in altered-bga-api (GET /api/games feed, ApiKeys:GameSync), keyed by the same BGA tournament id.

Change what BGA sends

altered-bga-api is the adapter. New envelope fields go in DecklistPayload / DeckContentPayload; the sealed contract to altered-draft stays the three query params + the Bearer.

Support a tournament ending

Declared tournaments have ends_at and a manual close (§14). For generic BGA tournaments nothing exists; options: a manual "archive" flag on sealed_pools, or joining altered-bga-api's Tournaments/Games by tournament_id.

Draft tournaments

Deferred by design; a draft is not a pure function of a seed, so it would need binding an already-completed draft_rooms result to a tournament id instead.

14.1 Stored pools

Every pool created after the lot-1 migration stores what it generated (sealed_pools.cards = { ref: count }, boosters = string[][], config = the config snapshot, created_by = 'page' | 'bga' | 'legacy'). src/lib/poolBuilder.js (buildPool) is the single generation entry point (same deterministic output as §4 for a legacy config, plus excludeBanlist); generation runs before the INSERT … ON CONFLICT DO NOTHING RETURNING *, so a card-data failure writes nothing. Reads go through loadPool(sub, row) (api/_lib/tournamentPool.js): stored contents when row.cards is set, else §4's regeneration (legacy rows). scripts/freeze-sealed-pools.mjs stores the older rows once after the migration — from then on no pool depends on the upstream set file's order. Idempotent. Deployed: docker exec altered-draft node scripts/freeze-sealed-pools.mjs (the image ships scripts/freeze-sealed-pools.mjs only, the container already has DATABASE_URL), once the new container serves, since the old code keeps creating rows without cards until then. Local: make db-freeze-pools (honours a DB_PORT override). §10.1 has the whole rollout. src/lib/poolBuilder.golden.test.js checks that buildPool on a legacy config reproduces the pre-storage regeneration bit for bit (and pins a digest of one draw), so a frozen pool is the pool its player already saw.

14.2 BGA resolution order

poolStore.bindTournamentId(sub, bgaId, bgaName), called by /api/tournament-bga-decklist and /api/tournament-pool-counts, now resolves in this order:

  1. The player's row for (sub, tournament_id = bgaId) → returned. Legacy-bound rows still get tournament_name refreshed from BGA; pools of a declared tournament keep the altered-draft name.
  2. A declared tournament with bga_tournament_id = bgaId (whatever its status, detached excepted) → getOrCreateTournamentPool(sub, tournament, { createdBy: 'bga' }): the player's attached pool, else a legacy pool already bound to that BGA id (adopted, never replaced), else a new stored pool from the tournament's config. Registered pools are created pre-bound (tournament_id = the BGA id, bound_at = creation), so step 1 finds them afterwards. Races on either unique index re-select the winner's row.
  3. Otherwise → the legacy pending preparation pool is bound, exactly as in §5.

Declared after BGA started. If players already have pools bound to that BGA id without a declared tournament (they are already playing it with the default format), the declaration takes their format (the submitted config is replaced, the form shows it locked as soon as the link is pasted) and adopts those pools in the same statement, so the tournament is locked from the start. If those pools do not all share one format, the declaration is refused (409 bga_tournament_mixed_formats). Pools still attached to a detached declaration count as such pools (§14.5 releases them anyway). Adopted pools get adopted_at, which is what detach uses to tell them from the pools created for the declaration.

14.5 Detach (moderators, squatting)

Any account can declare any BGA id, so a declaration can hijack a tournament someone else organizes; uniqueness then blocks the real organizer and cancel does not help (the BGA path ignores status). A moderator fixes it with PATCH { action: 'detach' } (tournamentStore.detachTournament, one transaction that locks the tournament row first):

  • the pools the declaration adopted (adopted_at set: they were already bound to that BGA id before it, see §14.2) are released: tournament_ref and adopted_at back to NULL, contents and deck untouched. They are ordinary bound legacy pools again, and the real organizer's declaration re-adopts them, imposing their format (§14.2);
  • the pools created for the declaration are deleted, played or not (their sealed_pool_games cascade); their decks on decks-api are left orphaned and those players start over;
  • detached_at is set and the BGA id is free again (tournaments_bga_tournament_id_live is partial on detached_at IS NULL). A pool insert racing with the detach is refused by its FOR SHARE guard (§5).

getTournamentByBgaId skips detached rows, so the next BGA call for that id goes to the real organizer's declaration (or, for a released pool, straight to that pool, step 1 of §14.2). The detached row stays as a read-only trace (status detached, any PATCH → 409 tournament_detached, DELETE still allowed). The confirmation re-reads the pool count at click time and states it, and says which pools are kept.

15. Glossary

sub
Keycloak subject (user id). The owner key of every pool.
nonce
Random UUID minted once per pool; the only secret-ish input of the seed.
pool
A player's sealed card pool. Stored on the row at creation since lot 1 (§14.1); older rows are regenerated until frozen.
normal pool
The single casual pool per player (kind = normal), resettable with a cooldown.
pending / preparation pool
A kind = tournament pool with tournament_id IS NULL. At most one per player.
bound pool
A tournament pool with tournament_id set; immutable.
binding
The one-time write of a BGA tournament id onto the pending pool, triggered by the first BGA deck-list call for a tournament nobody declared.
current format
The latest current_format row; the configuration of the normal and pending pools.
declared tournament
A row of tournaments: a BGA tournament an organizer registered on altered-draft with its own sealed config (§14).
attached pool
A pool with tournament_ref set: the player's pool for a declared tournament, created pre-bound to its BGA id (or a legacy pool adopted).
config
The sealed configuration object (spec §5.1): source set + boosters, heroes, uniques, ban list. Snapshotted on each pool.
organizer / moderator
Who declared a tournament / who may manage every tournament and detach one (TOURNAMENT_MODERATOR_ROLE, TOURNAMENT_MODERATORS).
detach
Moderator action against squatting: deletes the pools created for a declaration, releases the ones it adopted, and frees its BGA id (§14.5).
freeze
scripts/freeze-sealed-pools.mjs: stores the contents of pools created before storage existed.
envelope
The { v, env, mode, payload } JSON that the AlteredBGA game code base64-encodes into eventFormat or {id} (SetupTrait.php).
hydra collection
decks-api's list shape (hydra:member, hydra:totalItems, hydra:view) that BGA expects.
family / serial / window
A rare card slot (AX_106), a unique's serial number, and the serial ranges that map to a faction for that family.
OOF
Out-of-faction printing of a card (its _R2, or a unique serial in the other faction's window).
guaranteed unique
A unique appended to the pool outside the boosters (guaranteed_uniques).
Random / Invalid prefixes
Deck-name literals flagging an unreviewed auto-built deck / an illegal deck.
AlteredOps
Re:Union's GitOps deployment repo (Docker on their infra, Traefik, Scaleway secrets).
